# NoEscapeAC — Formal Ring-3 Threat Model & Observability Matrix

**Document Version:** Release 1.3 (v7.0 Architecture)  
**Architectural Constraint:** Strictly User-Mode (Ring-3). Zero kernel drivers, callbacks, hypervisors, or BYOVD components.

---

## 1. Threat Model Philosophy & Ring-3 Trust Boundary

A Ring-3 anti-cheat operates at the same CPU privilege level (`CPL=3`) as the game process and user-mode processes owned by the same user account. Consequently:
1. **The client is fundamentally untrusted.** Any secret embedded in the client binary can eventually be extracted by a determined reverse engineer; any purely client-side check can be patched if self-integrity and server attestation are bypassed.
2. **Defense-in-depth and cross-layer corroboration are mandatory.** In-memory anomalies, thread execution provenance, API/table integrity, behavioral kinematics, server-side visibility culling, and authenticated server heartbeats must reinforce one another so an attacker must simultaneously defeat orthogonal subsystems.
3. **Observability honesty.** Some threats (e.g., passive PCIe DMA reads on a motherboard with IOMMU disabled, or a custom Ring-0 driver hiding its own module entry via DKOM) cannot be directly observed from Ring-3 memory inspection alone. For those threats, Ring-3 defenses must pivot to **behavioral kinematics**, **server-integrated phantom decoys**, **server-side ESP visibility filtering (never replicating hidden enemy coordinates)**, and **system security posture attestation** (e.g., verifying IOMMU/VT-d/AMD-Vi and Code Integrity status).

| **A1. Standard DLL / Shared Library Injection** (`LoadLibrary`, `LD_PRELOAD`) | New image-backed module in process maps; untrusted file path; missing/untrusted Authenticode signature or unknown ELF Build-ID; `LD_PRELOAD` / `/etc/ld.so.preload` presence. | Win: `EnumProcessModules`, `VirtualQuery`, `WinVerifyTrust`. | **A2. Reflective DLL Loading & Manual Mapping** | Executable (`PROT_EXEC` / `PAGE_EXECUTE_*`) private/anonymous regions (`inode == 0` / `MEM_PRIVATE`); PE `MZ`/`PE` or ELF `\x7fELF` headers or section tables (`".text"`, `".rdata"`) in unbacked pages; loader stub signatures (`ReflectiveLoader`, `LdrLoadDll` resolvers). | Win: `VirtualQuery`. | **A3. Module Stomping / Hollowing** | Discrepancy between in-memory `.text` (`PT_LOAD` RX) bytes and clean on-disk PE/ELF section after masking legitimate relocations (`.reloc` / `.plt` / `.got`). | Win: `GetModuleFileNameA`, PE section parser. Linux: `/proc/self/maps`, ELF64 program/section header parser. | Module name, RVA offset of modified byte range, expected vs. actual SHA-256 hash. | Kernel-level page table remapping (shadowept / physical page swapping) if user-mode reads are intercepted by a hypervisor. | **Very High** (after relocation & CET `endbr64` normalization). | Yes (section hashes compared against server golden manifest). | High-confidence violation. |
| **A4. Inline Function Hooking & Trampolines** (`JMP rel32`, `FF 25`, `mov rax; jmp rax`) | Modified prologue at offset `0` or `+4` (post-`endbr64`); trampoline allocation in anonymous executable memory (`MinHook`, `Detours`, `PolyHook`, `Frida`, `Substrate`). | `Unhooker::InspectRoutine`, `MemoryScanner::ScanSignatures`, `IntegrityChecker`. | Function name, target address, 16-byte corrupted prologue vs. golden disk prologue, trampoline target module. | Legitimate overlays (Steam, Discord, GPU drivers) also place inline hooks on rendering/input APIs. | **High** for detection; **Medium** for malice attribution without provenance check. | Yes (prologue bytes & target module provenance). | Requires provenance check: hook pointing to unsigned/unbacked memory -> High Confidence; signed overlay -> Observation/Allowlist. |
| **A5. IAT / EAT & ELF GOT/PLT Manipulation** | Function pointers in PE Import Address Table (`IMAGE_DIRECTORY_ENTRY_IMPORT`), PE Export Table, or ELF `.rela.plt`/`.rela.dyn` GOT pointing to unbacked memory or unexpected modules. | `Unhooker::AuditImportExportTables`, `dl_iterate_phdr`, PE OptionalHeader DataDirectory parser. | Symbol name, GOT/IAT slot address, actual target address, owning module path (or `UNBACKED`). | Deep internal pointer swaps inside private heap structures not registered with `CanaryMonitor`. | **High** | Yes (resolved module provenance reported to server). | High-confidence violation if pointing to unbacked or unsigned injected module. |
| **A6. Sleeping / Encrypted Memory Payloads** | Non-executable (`RW`) anonymous pages containing single-byte XOR obfuscated `MZ`/`ELF` headers or known cheat framework data headers (`LC_MEM`, `VMMDLL`), or alternating `RW -> RX -> RW` protection transitions. | `MemoryScanner::DetectSleepingPayloads`, adaptive region permission history tracker. | Region base, XOR key (`0x01..0xFF`), decoded header snippet, permission transition count. | Strongly encrypted (AES/ChaCha20) payloads while asleep with no plaintext metadata and no RX pages. | **High** (when XOR header + section markers or `RW->RX` transitions are observed). | Forensic payload verifiable by server. | Corroborated anomaly / High-confidence violation. |
| **A7. Game State & Heap Tampering** | Modification of registered critical game variables or surrounding 64-bit dynamic rolling XOR canary guards. | `CanaryMonitor::VerifyCanaries`, `ObfuscatedValue<T>` rolling XOR wrapper. | Corrupted canary ID, expected vs. observed guard value, variable address. | Unprotected game variables not wrapped in `ObfuscatedValue` or registered with `CanaryMonitor`. | **Very High** (zero false positives unless game has a memory corruption bug). | Server authoritative state check. | High-confidence violation. |
| **A8. Unauthorized Thread Execution** | Thread start address or current instruction pointer (`RIP`) residing in anonymous/unbacked memory or outside any valid loaded module's executable segment. | Win: `CreateToolhelp32Snapshot(TH32CS_SNAPTHREAD)`, `NtQueryInformationThread(ThreadQuerySetWin32StartAddress)`, `GetThreadContext`. Linux: `/proc/self/task/*/stat`, `/proc/self/task/*/syscall`. | Thread ID (`TID`), start address, current `RIP`/stack pointer, memory region backing status. | Thread hijacking that temporarily redirects a legitimate thread and returns before the next poll (mitigated by stack/canary/hook checks). | **Very High** | Forensic thread record sent to server. | High-confidence violation. |

### Category D: Behavioral & Gameplay Threats

| Threat Vector | Observable Signals in Ring-3 | User-Mode Interfaces Used | Available Evidence | What Remains Invisible in Ring-3 | Signal Reliability | Server Verifiable? | Safe Enforcement Role |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **D1. Snap Aimbots & Silent Aim** | Extreme angular velocity (`>1200 deg/s`) followed by instantaneous zero-velocity lock (`<0.5 deg/s`) within a single tick, or shot view-angles diverging from camera trajectory. | `AimAnalyzer::PushSample`, `CheckInstantSnap`. | Angular velocity, acceleration, jerk, post-snap velocity, input trail in `BlackboxRecord`. | Low-FOV "humanized" aim assistance on a single flick (requires multi-window statistical accumulation). | **Medium** for 1 snap; **Very High** across repeated multi-window occurrences. | **Yes — 100% Server Verifiable** via tick angle stream. | Multi-occurrence statistical correlation + server verification. |
| **D2. | **D3. | **D4. Triggerbots & Auto-Fire** | Sub-human reaction latency (`<45 ms` mean or near-zero standard deviation `<3 ms`) between target-crosshair intersection and fire input across multiple engagements. | `AimAnalyzer::RecordTargetAcquisition`, `RecordWeaponFire`. | Mean reaction time (ms), stddev (ms), sample count. | Single lucky pre-fire (prevented by requiring `>=5` engagements). | **Very High** over `>=5` shots. | **Yes — Server Verifiable.** | High-confidence behavioral violation. |
| **D5. Synthetic Mouse Input / Polling Quantization Anomalies** | Zero-jitter inter-event timestamps (`stddev == 0.0` over `>=32` samples) or impossible sub-millisecond synthetic timer bursts inconsistent with physical USB HID polling (`125/250/500/1000/2000/4000/8000 Hz`). | `AimAnalyzer::PushSample` interval analyzer. | Timestamp delta mean, jitter stddev, quantization entropy. | Hardware USB inline injection with simulated jitter. | **Medium-High** | Client telemetry + server tick correlation. | Corroborating signal for behavioral detections. |
| **D6. Wallhacks / ESP (In-Process, External, or 2-PC Radar)** | Player locking crosshair onto invisible **Phantom Decoy** entities that have no visual model/audio, or pre-aiming through solid occluders. | **D7.
