## 1. Executive Strategy & Guiding Principles

In competitive anti-cheat engineering, **a false positive ban is exponentially more destructive to community trust than a delayed detection**.
NoEscapeAC operates on a strict mathematical corroboration model:
- **Zero Bans on Weak Heuristics Alone:** No single heuristic signal (e.g. DMA bus jitter, a blacklisted process name in the background, or an unrecognized window overlay) may ever trigger an automated permanent ban.
- **Independent Family Corroboration:** High-severity enforcement actions require multiple uncorrelated evidence signals across independent subsystem families.
- **Graceful Escalation:** Progressive mitigation tiers allow suspicious telemetry to be audited or restricted on the server without immediately terminating legitimate players.

## 2. Evidence Categorization & Confidence Tiers

Every finding generated by NoEscapeAC is classified into an explicit Confidence Level:

| Confidence Tier | Criteria | Automatic Ban Eligible? | Typical Actions |
|---|---|---|---|
| **Tier 0: OBSERVATION** | Single statistical anomaly (e.g., minor memory bus latency spike during disk I/O, unrecognized utility running). | **NO** | Telemetry logged in client blackbox; no penalty. |
| **Tier 1: SUSPICION** | Repetitive heuristic anomaly (e.g., fast mouse flicks, unexpected window overlay). | **NO** | Increase audit loop frequency; activate `PhantomMonitor` decoys. |
| **Tier 2: CORROBORATED_ANOMALY** | Two distinct detection families match (e.g., process name match + suspicious PCIe device, OR aim jitter + high mouse polling). | **NO** (Match restriction only) | Server-side shadow matchmaking; server-side ESP filtering activated. |
| **Tier 3: HIGH_CONFIDENCE_VIOLATION** | Unambiguous tampering proof (e.g., anonymous RWX executable memory, confirmed MinHook detour on core OS library, known PCILeech hardware ID). | **YES** | Hardware ID ban + blackbox diagnostic dump generation. |
| **Tier 4: INDEPENDENTLY_VERIFIED** | Cryptographic or server-authoritative proof (e.g., failed HMAC remote code attestation, crosshair locked on invisible server phantom decoy). | **YES** | Immediate session eviction + permanent enforcement. |

## 3. Heuristic Dampening Rules (`EvidenceCorrelator`)

The `EvidenceCorrelator` enforces hardcoded suppression rules on weak signals:
1. **DMA Memory Bus Latency Jitter Alone:**
   - Disk intensive operations, PCI bus contention from legitimate NVMe drives, or background rendering can induce memory bus latency spikes.
   - *Rule:* Jitter anomaly alone carries a maximum threat score of 30 and can never cross the ban threshold without physical hardware confirmation (`PciDeviceInfo` with suspicious characteristics) or memory tampering.
2. **Process Name Matching Alone:**
   - Players frequently run background development environments (e.g., Python scripts, Visual Studio, debugging utilities named `injector.exe` or `test.exe`).
   - *Rule:* Process name matches without active open memory handles to the game PID (`PROCESS_VM_READ/WRITE` or Linux `/proc/[pid]/mem`) are classified as low-severity heuristics and capped below the enforcement ceiling.
3. **Window Overlays & Recording Tools:**
   - Valid game capture software (OBS Studio, GeForce Experience, Discord Stream Overlay, Steam Overlay) creates transparent topmost windows.
   - *Rule:* Overlays are verified against known vendor certificates, executable hashes, and valid process IDs before flagging. Unidentified overlays trigger telemetry, not bans.
4. **Sub-Millisecond Mouse Flicks & Axis-Aligned Pans:**
   - Pro players using high-DPI gaming mice (4000 Hz / 8000 Hz) can generate high velocity angular changes.
   - *Rule:* Kinematic analysis requires sustained non-human metrics over multiple sequential time windows ($>10$ frames) and evaluates curvature and jerk, rather than raw velocity alone.

## 4. Legitimate Software Whitelisting

### 4.1. Certified Overlays
- **Steam In-Game Overlay:** `gameoverlayrenderer64.dll`, `gameoverlayui.exe`, `libgameoverlayrenderer.so`
- **Discord Game Overlay:** `DiscordHook64.dll`
- **NVIDIA GeForce Experience:** `nvspcap64.dll`
- **OBS Studio Game Capture:** `graphics-hook64.dll`
- **RivaTuner Statistics Server (RTSS):** `RTSSHooks64.dll`

### 4.2. Developer Environments & Sanity Buffers
- **AddressSanitizer / ThreadSanitizer:** Allocates massive shadow memory regions (e.g., multi-gigabyte reservations). The `MemoryScanner` explicitly detects sanitizer shadow masks and excludes them from anonymous scan budgets.
- **Development Boards:** FTDI USB-to-UART bridges, Raspberry Pi debuggers, and Xilinx developer boards are checked for legitimate developer configurations before assessing DMA cheat risk.

## 5. Gradual Enforcement Pipeline

```
[Telemetry Signal] 
       |
       v
+-----------------------+
|  EvidenceCorrelator   | ---> Single Weak Heuristic? ---> Log & Observe Only
+-----------------------+
       | Multi-family Corroboration
       v
+-----------------------+
|   Server Coordination | ---> Authoritative Desync Check
+-----------------------+
       |
       +---> Score >= 40  ---> Flag for Review / Dynamic Decoys
       +---> Score >= 70  ---> Match Restriction / Shadow Pool
       +---> Score >= 100 ---> Session Termination & HWID Ban
```

## 6. Audit & Rollback Workflow

1. **Encrypted Blackbox Forensics:** Whenever an enforcement event occurs, the engine writes an AES-256-GCM encrypted diagnostic dump (`/tmp/noescape_blackbox_*.dmp`). This file contains the exact sequence of events, memory addresses, and timestamps that precipitated the decision.
2. **Cryptographic Proof Chain:** Every ban report sent to the backend includes an HMAC-SHA256 signature bound to the client's hardware fingerprint and timestamp, ensuring ban decisions cannot be forged or manipulated by third parties.
3. **Automated Rollback Capability:** If an updated heuristic rule produces an anomalous elevation in score across the player base, operations engineers can dynamically adjust scoring multipliers on the backend server or issue cryptographic rollback tokens.
