# NoEscapeAC — Detection Gap Analysis & Engineering Remediation Plan

**Document Version:** Release 1.3 (v7.0 Architecture)  
**Purpose:** Map every gap between the pre-1.3 implementation and our Ring-3 Threat Model (`RING3_THREAT_MODEL.md`) to concrete, verifiable engineering solutions.

---

## 1. Gap Summary & Prioritized Remediation Matrix

| Gap ID | Subsystem | Identified Gap (Pre-Release 1.3) | Security / Reliability Impact | Release 1.3 Engineering Solution | Verification Method |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **GAP-01** | Build & SIMD (`CMakeLists.txt`, `pattern_scanner.cpp`) | MSVC globally enabled `/arch:AVX2` while `NOESCAPE_RUNTIME_DISPATCH` was disabled on `_MSC_VER`. | Crash (`STATUS_ILLEGAL_INSTRUCTION`) on non-AVX2 CPUs under MSVC builds. | Remove global `/arch:AVX2` from `CMakeLists.txt`; implement portable `__cpuidex` + `_xgetbv` runtime AVX2 detection across GCC, Clang, and MSVC. | Unit tests verifying `PatternScanner::HasAvx2Support()`, SSE2, and scalar paths. |
| **GAP-02** | Trust & Attestation (`crypto_util`, `panel_client`) | Symmetric `secret_key_` used both to sign client telemetry and verify server `/check` & `/heartbeat` responses; static default key. | Extracting `secret_key_` from client binary allows local forgery of server `OK` responses. | Add asymmetric server signature verification (`VerifyServerSignature` with P-256 / Ed25519 / keyed public-verification token), key rotation IDs (`key_id`), challenge expiration, and anti-rollback version verification. | Cryptographic & protocol tampering unit tests (`test_crypto.cpp`, `test_audit_remediation.cpp`). |
| **GAP-03** | Evidence & Enforcement (`types.hpp`, `engine.cpp`) | Flat 6-field `DetectionEvent`; single `FATAL_BAN` or raw score threshold immediately triggers ban without confidence tiers or corroboration. | Weak heuristics (e.g., process name, single timing spike, or OS config) could cause false-positive bans; no `REPORT_ONLY` or `SHADOW` modes. | Introduce `ConfidenceLevel`, `DetectionCategory`, `EnforcementMode`, rich 16-field `DetectionEvent`, and `EvidenceCorrelator` requiring multi-signal corroboration for weak signals. | Unit tests covering all 5 enforcement modes, confidence promotion, and single-weak-signal ban prevention. |
| **GAP-04** | Watchdog Resilience (`engine.cpp`) | `WatchdogLoop` checked `now - last > 3000ms` without measuring its own `100ms` sleep duration. | Laptop suspend/resume or OS-wide freeze causes false `HEARTBEAT_TAMPERING` alert. | Measure watchdog iteration delta (`watchdogElapsed`); if `watchdogElapsed > 1500ms`, classify as system sleep/stall and resynchronize heartbeat timestamp instead of flagging tampering. | Simulated sleep/stall regression test. |
| **GAP-05** | Memory Forensics — Thread Provenance (`memory_scanner.cpp`) | No inspection of active thread start addresses or instruction pointers (`RIP`). | Injected shellcode threads running in unbacked pages or stomped regions go unnoticed by thread-level forensics. | Implement `MemoryScanner::AuditThreadProvenance()` inspecting `/proc/self/task/*` on Linux and `ThreadQuerySetWin32StartAddress` + `GetThreadContext` on Windows. | Thread provenance unit test with synthetic anonymous-page thread execution. |
| **GAP-06** | Memory Forensics — Module Provenance (`memory_scanner.cpp`) | Loaded modules were not hashed (SHA-256), checked for ELF `NT_GNU_BUILD_ID`, or verified via Windows `WinVerifyTrust`. | Unable to distinguish legitimate signed system/overlay libraries from unsigned injected modules. | Implement `MemoryScanner::QueryModuleProvenance()` & `AuditModuleProvenance()` computing SHA-256 disk digest, ELF Build-ID, and Windows Authenticode status. | Module provenance unit test verifying self binary SHA-256 and ELF Build-ID extraction. |
| **GAP-07** | Memory Forensics — Adaptive Scanning & Signed DB (`memory_scanner.cpp`, `signature_database.cpp`) | Re-scanned unchanged clean regions on every cycle; `SignatureDatabase` lacked versioning, deduplication, and signed remote update bundles. | Unnecessary CPU overhead on large address spaces; inability to safely push hotfix signature updates. | Add adaptive region-hash cache, configurable scan time budgets (`scanBudgetMs`), P50/P95/P99 telemetry, and HMAC/signature-verified versioned `SignatureBundle` import/export. | Adaptive scan benchmark & signed bundle verification tests. |
| **GAP-08** | API & Table Integrity (`unhooker.cpp`) | Only checked 16-byte function prologues and `dlsym(RTLD_DEFAULT)` vs `libc`; no PE IAT/EAT or ELF GOT/PLT sweep; unconditional byte overwrite. | Misses GOT/PLT or IAT pointer redirection hooks that leave function prologues intact. | Implement `Unhooker::AuditImportExportTables()` parsing ELF `.rela.plt`/`.rela.dyn` (`PT_DYNAMIC`) and PE `IMAGE_DIRECTORY_ENTRY_IMPORT`/`EXPORT`, plus configurable `RepairPolicy`. | GOT/IAT hook simulation and repair policy unit tests. |
| **GAP-09** | Process & Handle Forensics (`process_analyzer.cpp`) | Windows `DetectExternalMemoryReaders()` was an empty `#if !defined(_WIN32)` stub; Linux missed `/proc/*/map_files`. | External `OpenProcess(PROCESS_VM_READ)` cheats on Windows were invisible to `ProcessAnalyzer`. | Implement Windows `NtQuerySystemInformation(SystemExtendedHandleInformation)` handle scanner (with dynamic buffer resizing and version-safe fallback) and Linux `/proc/*/map_files` check. | Cross-platform handle & process provenance tests. |
| **GAP-10** | ESP Defense & Server Integration (`phantom_monitor.cpp`, `server_integration.hpp`) | `PhantomMonitor` only tracked local coordinate arrays; no server-authoritative ESP visibility culling module existed. | Passive wallhacks and 2-PC DMA radars that avoid locking onto decoys still receive all enemy coordinates if the server replicates them. | Create `ServerEspFilter` (`include/noescape/server/server_integration.hpp`) implementing FOV frustum + line-of-sight occlusion culling, fog-of-war distance gating, radar minimization, and server-integrated decoy policies. | Server visibility culling, occlusion raycast, and decoy interaction tests. |
| **GAP-11** | Behavioral & Input Telemetry (`aim_analyzer.cpp`) | Only evaluated 3 angle heuristics (`InstantSnap`, `PerfectLinearity`, `ArtificialSmoothing`). | Missed synthetic mouse polling timers, automated recoil compensation scripts, and triggerbot reaction-time distributions. | Extend `AimAnalyzer` with polling-interval quantization/jitter analysis, recoil compensation variance tracking, triggerbot target-to-shot latency analysis, and multi-window session statistical counters. | Synthetic macro polling, recoil script, and triggerbot latency unit tests. |
| **GAP-12** | Hardware & DMA Modeling (`dma_detector.cpp`) | Lacked IOMMU (`VT-d`/`AMD-Vi`) kernel enforcement detection and structured hardware confidence tiers. | Cannot distinguish a DMA-protected host (IOMMU active) from an exposed host, nor separate timing jitter from corroborated DMA evidence. | Add `CheckIommuStatus()`, `HardwareConfidenceLevel` enum (`KNOWN_LEGITIMATE` to `CORROBORATED_DMA_EVIDENCE`), and ensure timing/VID signals alone never auto-ban without corroboration. | IOMMU status & hardware confidence tier tests. |
| **GAP-13** | Blackbox Privacy & Cryptography (`blackbox.cpp`) | Deterministic SHA-256 IV and unredacted OS user file paths in forensic dumps. | Repeated dumps at same millisecond share keystream prefix; user account names leaked in paths (`/home/<user>/`, `C:\Users\<user>\`). | Generate 16-byte IVs via `std::random_device` mixed with high-resolution entropy; add `RedactSensitivePaths()` stripping OS usernames from all forensic strings. | IV uniqueness and PII path redaction unit tests. |

## 2. Non-Goals & Ring-3 Architectural Boundaries

To maintain strict adherence to our Ring-3 engineering mandate:
- **No kernel drivers or BYOVD:** We do not load `.sys` or `.ko` modules, register `ObRegisterCallbacks`, or read physical memory from Ring-0.
- **No invasive third-party process tampering:** We do not inject DLLs into other processes or modify memory outside our own process (`Unhooker` self-repair is strictly restricted to our own process and controlled by `RepairPolicy`).
- **No privacy-invasive file harvesting:** `ArtifactAnalyzer` and `BlackboxDumper` inspect only process/security posture metadata and redact local OS usernames before persistence or transmission.
